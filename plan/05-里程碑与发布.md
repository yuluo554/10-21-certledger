> **M1 出口实测**（2026-10-21，本机 3.12.10 + OpenSSL 3.5.6）：
> `gen.sh --determinism` → 29 个文件两次生成字节全等 + 3 个容器按 alias 表比对通过；
> `gen.sh --check` → 17 用例 / 字节级 31 项 / alias 表 3 项 / 容器字节跳过 3 项；
> `pytest -q` → 101 passed, 1 skipped。
>
> **与 `plan/04` §1.1 的三处实现口径**（写下来是因为它们会改变样本形态，不是细节）：
> ① **truststore 混私钥**用 PKCS#12 的"私钥 bag + 带 friendlyName 的外来证书 bag"表达
> （`PrivateKeyEntry`/`trustedCertEntry` 是 JKS 词汇；PKCS#12 走 `cryptography`，其 bag 结构即契约）；
> ② **没有 ECDSA 样本**（ECDSA 签名用随机 nonce，两次生成字节必不同，与"同参数两次同字节"冲突）；
> ③ **没有 JKS 样本**（JKS 字节内嵌创建时间戳且需要可选依赖 `keytool`，会让真值随机器而变）——
> 两者都在 `fixtures/gen.py` 模块注释与 `plan/04` §1.3 记明，留给容器路线。

## 三、发布口径

- **附件形态**：手工源码包（`python -m build --sdist` 的产物 **或** `git archive` 归一包），
  **不用** GitHub 自动生成的 zipball（其 sha256 本地无法复算）。
- **sha256 落点**：只写进 **Release 正文**（不动仓库树）；包内文档只写复验方法。
- **tag 树内不留字面值**：`plan/RELEASE-M6.md` 的 tag/OID/包哈希一律写"见 `git rev-parse v0.1.0`"，
  字面值写进 tag 之后的追加提交。
- **版本号**：`src/certledger/__init__.py::__version__` 是唯一来源；
  `pyproject.toml` 走 `dynamic`；README 顶部标同名版本；一条测试断言三处一致。
