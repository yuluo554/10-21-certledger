## 一、分层

```
┌─────────────────────────────────────────────────────────────┐
│ cli.py              argparse 五子命令 · 退出码 0/1/2 · 参数校验 │
├─────────────────────────────────────────────────────────────┤
│ pipeline.py         一条命令的编排：collect → inventory →     │
│                     hygiene → report（阶段间只传内存对象）     │
├─────────────────────────────────────────────────────────────┤
│ collectors/         遍历 · 内容嗅探 · 后端探测 · 跳过原因码     │
│ parsing/            PEM 分块 · X.509 · 私钥 · PKCS#12 · 指纹   │
│ inventory.py        归一化台账：按指纹合并 · SPKI 配对          │
│ hygiene.py          九类规则 + 策略驱动 + finding 生成          │
│ containers.py       alias 表 · 容器级信号                      │
│ render/             JSON / Markdown 双格式 · 稳定排序 · 打码    │
├─────────────────────────────────────────────────────────────┤
│ model.py            统一记录模型（唯一真值结构）                │
│ policy/loader.py    策略加载与校验（零默认字面量）              │
│ timebase.py         --as-of 解析（必填、唯一时间基准）          │
│ errors.py           CliError → 退出码 2 的唯一出口             │
└─────────────────────────────────────────────────────────────┘
```

四条分层纪律：

1. **单向依赖**：上层可依赖下层，同层之间只允许"左侧依赖右侧"（cli → pipeline → 领域模块 → model）；
   领域模块**不得** import `cli`／`argparse`。报告层不得反过来调用 hygiene（渲染层零判定）。
2. **解析与判定分家**：`parsing/` 只产出"证书/私钥是什么"，不产出任何 `EXPIRED`/`WEAK` 结论；
   所有判定在 `hygiene.py`，且阈值只来自 `policy/`。
3. **单一时间源**：`--as-of` 解析后以 `int` 秒在进程内传递（`timebase.AsOf`），
   **任何模块不得读 `datetime.now()` / `time.time()`**（K2，用 AST 守门测试断言）。
4. **单一指纹入口**：所有 SHA-256 只经 `parsing/fingerprint.py`（K1），
   避免出现"某处先重新编码再哈希"的第二条路径。

## 三、技术选型与理由

| 项 | 选型 | 理由 | 被否方案 |
|---|---|---|---|
| 语言 | Python ≥ 3.10 | 目标受众（SRE/运维）机器上普遍可装；3.10 提供 `match`／`X \| None`／`zip(strict=)`，同时不把 3.9 系统 Python 用户全挡在门外 | 3.8（社区已 EOL，且写不出 `X \| None`，代码噪声大）；3.12（受众面收窄） |
| 解析底座 | `cryptography>=42` | X.509 / PKCS#12 / PKCS#8 / SPKI 全部原生支持，且能直接拿到 DER 原始字节做哈希（K1）；不需要自己实现 ASN.1 | 纯 stdlib 自研 ASN.1（解析器 bug 会直接污染指纹，M2 要额外做逐字段对账）；`openssl` 子进程（每文件 fork 一次，大目录扫描慢一个量级，且输出格式随版本漂移） |
| JKS / JCEKS | `keytool -list -v` 子进程解析 | 私有格式无 RFC（`data/README.md` §2.5），JDK 自带实现行为稳定；pyjks 已停更（D2） | pyjks（停更）；自研 JKS（时间黑洞） |
| CLI 框架 | `argparse`（stdlib） | 零额外依赖；`SystemExit(2)` 语义与退出码 2 天然一致（入口统一捕获） | click/typer（多一个依赖，收益仅是写法糖） |
| 输出 | JSON（机读）+ Markdown（人读），同一内存模型渲染 | 报告要能进 git／工单／做 baseline diff，两种格式必须同源 | 只出 JSON（人读体验差）；只出 Markdown（无法 diff） |
| 测试 | `pytest`（dev extra） | 本项目需要大量参数化与 `tmp_path` 夹具 | unittest（样板过多） |
| 打包 | `setuptools` + `src/` 布局 + `[project.scripts]` | 与 `plan/01` §三.1 要求的 `certledger` 入口一致；src 布局防"误 import 工作目录" | flit/hatch（生态兼容性不如 setuptools） |
| 许可证 | MIT | 最短、最通用，便于公司内部直接采用 | Apache-2.0（更长，专利条款对本项目无实际增益） |

**依赖面明确为两项**：运行时 `cryptography`；测试期 `pytest`（`[project.optional-dependencies] dev`）。
`keytool` **不是** Python 依赖，而是**可选外部能力**：缺失时容器视图降级为 `CONTAINER_UNREADABLE`，
进程不失败（D2 / D11）。

## 四、构建

```bash
py -3.12 -m venv .venv
./.venv/Scripts/python.exe -m pip install -e ".[dev]"     # Git Bash；PowerShell 用 .venv\Scripts\python.exe
certledger --version
pytest -q
```

- **版本单一来源**：`src/certledger/__init__.py` 的 `__version__`；
  `pyproject.toml` 用 `dynamic = ["version"]` + `[tool.setuptools.dynamic] version = {attr = "certledger.__version__"}`，
  **不写第二处字面量**。测试断言 `importlib.metadata.version("certledger") == certledger.__version__`。
- **随包数据**：`src/certledger/data/*.json` 通过 `[tool.setuptools.package-data]` 打入 wheel，
  运行期用 `importlib.resources` 读取——**不得**按源码相对路径读（装成 wheel 后会失效）。
- **入口两形态**：`console_scripts: certledger = certledger.cli:main` 与 `python -m certledger`，
  两者必须走同一个 `main(argv=None) -> int`。
- **构建产物**：`python -m build` 产 sdist + wheel；M6 的 Release 附件取**手工源码包**（A 方案，
  `plan/00` 发布口径），不从 GitHub 自动 zipball 取。

## 五、退出码与错误分级

| 码 | 语义 | 落点 |
|---|---|---|
| `0` | 无 finding 达到 `--fail-on` 门槛（含仅有 WARN/INFO） | `report` / `hygiene` |
| `1` | 有 finding 达到 `--fail-on` 门槛（默认 `ERROR`） | 同上 |
| `2` | 输入/策略/参数错误 | `errors.CliError` **唯一出口**，`cli.main` 捕获后返回 2 |

- **不设"未实现"退出码**。骨架期未接通的能力（系统后端、PKCS#7、OpenSSH）产**可见的
  `SOURCE_UNAVAILABLE` / `PARSE_UNSUPPORTED` 记录**并照常返回 0/1——"没看"必须能在报告里被指认，
  但不该把"这台机器缺能力"判成采集失败（D11）。这条替代了早期草案里的临时码 `3`，
  因此**不存在需要退役的幽灵语义**。
- `argparse` 对未知子命令/缺必填参数抛 `SystemExit(2)`；`main` 捕获 `SystemExit` 并**归一为 2**，
  避免"某些入口答 2、另一些答 1"的漂移。

## 六、确定性设计（贯穿三层）

| 层 | 约束 |
|---|---|
| 哈希 | 输入一律 DER 原始字节；不做"解析 → 重编码 → 哈希" |
| 排序 | 遍历：规范化路径（大小写归一 + NFC）；`sources[]`：`(kind, path, alias)`；finding：`severity → code → subject → fingerprint`；过期表：`not_after` 升序 |
| 序列化 | JSON 键序 = schema 声明序（`model.py` 里显式构造有序 dict）；`ensure_ascii=False`；`indent=2`；行尾 `\n` |
| 时间 | 唯一时间基准 = `--as-of`；报告不嵌运行时间戳/耗时 |
| 隐私 | 不写主机名、用户名；绝对路径默认打码（`render/redact.py`，`--no-redact` 才显示） |

## 七、安全与隐私边界（架构层强制）

- **零网络**：`collectors/`、`parsing/`、`hygiene.py` 不得 import `socket`/`http.client`/`urllib.request`/
  `requests`；用 AST 守门测试断言（比 code review 可靠）。
- **口令处理**：容器口令只从 `--password-env <VAR>` 指向的环境变量读取，**不落盘、不进报告、
  不进异常消息**；报告与诊断里以 `<redacted>` 代替。
- **真实资产**：`.gitignore` 拦截 `*.pem/*.key/*.p12/*.jks/...` 与 `fixtures/out/`；
  测试与样本一律现场生成。
- **子进程**：仅 `keytool`（容器视图）一处，参数列表固定、`shell=False`、超时 20s；
  失败 → `CONTAINER_UNREADABLE`。
