# 10-21-certledger · 本地密码学资产台账（题目文档）

> - **性质**：不参赛项目题（无赛事锚点；含金量锚点=受众面广度 + 确定性可评测 + 开源空白）
> - **目标产出**：仓库 `10-21-certledger`（CertLedger / 本地密码学资产台账），发布 GitHub **公开仓库**，署名 `yuluo554`
> - **版本史**：v1 2026-10-20（定稿）
> - **交付形态**：**纯本地 Python CLI**（唯一形态；零网络、零远程握手、零守护进程）
> - **定位宣言**：ChainWarden 回答"这张证书有没有问题"，我们回答"**这台机器上有哪些证书和私钥，谁配谁**"。
>   给一台机器做一次家底盘点：有什么证书、有什么私钥、谁配谁、谁过期、谁重复、谁没人用、强度够不够。
>   过期表只是其中一列。**这是台账，不是过期提醒器**——只提醒不记账的工具已经有一打，缺的是那张能对上的表。

## 一、介绍

### 1.1 痛点：缺的不是"提醒"，是"清单"

证书过期本身不是新闻，**不知道自己有哪几张**才是。SRE 现场的抱怨几乎从不指向"没告警"，而指向"没人知道这张存在"。

You get: Internal CA sprawl (and no single source of truth); **Certs embedded in keystores, containers, or staging systems that nobody owns anymore**; 'Temporary' certs that live on for years…" <https://news.ycombinator.com/item?id=44722816>

最后两条最值得注意：**连卖商业方案的人都承认"发现难调"，而且一旦有了台账，后面的生命周期管理才变简单**。这句话是本项目的立项依据——先做台账，不做自动续期。

### 1.2 最大风险：不是空白，是 `ChainWarden` 77★

**必须写在题面前面的风险**：`ChainWarden`（**77★**，2025-10 建仓，2026-09-03 push）已经占了"离线 PEM 审计"这个词。它用 stdlib 实现，提供 `--as-of` 确定性判定，expiry / weak / chain 三件事都做了。

**它的 README 明说的边界**（✅ 逐句核对）：

- **不验签**（不做签名验证）；
- **不查吊销**；
- **只量 RSA**（不做 EC/Ed25519 的强度判定）；
- **不处理 P12 / JKS / 私钥 / 系统库**。

这四条边界就是本题的入口：ChainWarden 的输入面是"一个 PEM 文件"，本题的输入面是"**一台机器**"。差异必须在 **README 首屏一句话说清**（写作纪律见 `plan/00` 决策记录 D1）：

> "ChainWarden 审的是**一个 PEM 文件**；CertLedger 盘的是**一台机器**——容器里的别名、系统库里的条目、孤零零躺在备份目录里的私钥，都进同一张按指纹交叉引用的表。"

`chain` 能力本文脉不争：ChainWarden 已做，openssl `verify` 与 certigo 也都做（见 §1.3、§六），本题首期**不做链验证**。

### 1.5 规范依据（✅ 逐条核对原文；台账明细见 `data/README.md` §二）

- **X.509**：RFC 5280 Validity §4.1.2.5（UTCTime §4.1.2.5.1 / GeneralizedTime §4.1.2.5.2）、Key Usage §4.2.1.3、Basic Constraints §4.2.1.9、Name Constraints §4.2.1.10、SAN §4.2.1.6、EKU §4.2.1.12、CRL DP §4.2.1.13、Certificate Policies §4.2.1.4、SKI §4.2.1.2；路径验证 §6（首期不做，列 v2）。
- **密钥强度（不自创阈值，只引两家）**：CA/B Forum TLS BR v2.3.1 **§6.1.5 Key sizes**——"Ensure that the modulus size, when encoded, is at least 2048 bits"、"Ensure that the key represents a valid point on the NIST P-256, NIST P-384 or NIST P-521 elliptic curve"、"**No other algorithms or key sizes are permitted.**"；NIST SP 800-131A Rev.2——RSA "length of the modulus n shall be 2048 bits or more to meet the minimum security-strength requirement of 112 bits"、ECDSA len(n) ≥ 224、SHA-1 "disallowed for digital signature generation"（verification 属 legacy use）。
- **"2048 够不够"必须精确表述**：NIST SP 800-57 Pt1r5 表 2 中 RSA 2048 = **112-bit**；同文件 §1.1 与 SP 800-131A Rev.2 记载 "SP 800-57, Part 1 includes a **transition to a security strength of 128 bits in 2030**"；SP 800-57 Pt1r5 表 4 中 112-bit 在 "Applying protection" 列为 "through 2030 acceptable / **2031 and beyond disallowed**"。→ **正确说法是"RSA 2048 在 NIST 口径下 2031 年起不再允许用于施加保护"，不是"现在已弱"**。工具因此必须做成**带出处可配置策略**，默认 `WARN` 而非 `ERROR`。
- **公网有效期政策（提示层，不参与本地合规判定）**：CA/B BR 时间表——2026-03-15 起最长 200 天、2027-03-15 起 100 天、2029-03-15 起 47 天（BR.md 日期表 + §6.3.2 原文核对）。
- **主机名匹配**：RFC 9525 §6 / §6.3（DNS-ID）。该文档 §1 明写 "This document **obsoletes RFC 6125**"，且正文指出 CN RDN **MUST NOT** 用于识别服务。→ **本项目的文档与代码注释不得引用 RFC 6125 §6.4.4 作现行依据（已废弃）**。
- **编码层**：PEM = RFC 7468、PKCS#12 = RFC 7292、EC 私钥 = RFC 5915、通用私钥 = RFC 5958 OneAsymmetricKey。
- **JKS/JCEKS 无 IETF 规范**：属 Sun 私有格式，**必须明说无 RFC 依据**，只能按实现逆向——这是 M5 的设计前提，不是脚注。

## 二、任务要求

首期 **5 个模块**，其余留扩展项。每个模块写清 输入 / 输出 / 确定性纪律。

### 模块①：采集器 `collectors`

- **输入**：一个或多个根路径（递归）、显式文件列表、后端选择符（`--source auto|linux|windows|macos|none`，默认 `auto`）。
- **格式嗅探**（按内容而非扩展名）：PEM（含证书/私钥/PKCS#7 块，多块文件逐块展开）、DER、PKCS#7、PKCS#12、JKS、JCEKS、PKCS#8、OpenSSH 公钥（`ssh-rsa` / `ssh-ed25519` 等起始行）。嗅探只看固定长度的前缀窗口（窗口长度是**策略常量**，落点见 `data/README.md` §数值口径，不在代码里散落字面量）。
- **输出**：候选流（`path` / `offset` / `detected_format` / `container_alias` / `sha256(file)` / `parse_status`），以及每个后端一行状态记录。
- **确定性纪律**：
  - 目录遍历按**规范化路径**排序（大小写归一 + Unicode NFC），不依赖文件系统返回顺序；
  - **默认不跟随符号链接**（防环、防越界），跟随需显式开关；
  - 跳过的文件必须留**原因码**（`SKIP_BINARY` / `SKIP_PERMISSION_DENIED` / `SKIP_TOO_LARGE`），不静默；
  - **后端不可用不是错误**：统一降级为一条 `SOURCE_UNAVAILABLE` 记录（含后端名与探测失败原因），进程**不因此非零退出**；
  - **零网络**：本模块不存在任何发起连接的代码路径。

### 模块②：归一化台账 `inventory`

- **输入**：模块①的候选流。
- **输出**：统一记录模型——
  - `cert`: `fingerprint_sha256`（证书 DER 的 SHA-256）+ `spki_sha256` + `subject` / `issuer`（原始 DER + 展示串） + `san`（按 RFC 9525 DNS-ID 归类） + `not_before` / `not_after`（UTC，保留原始精度） + `key_algo` / `key_bits` / `curve` + `sig_algo` + `key_usage` / `extended_key_usage` + `sources[]` + `subject_key_id`；
  - `key`: `spki_sha256`（由私钥推导公钥后计算）+ `key_algo` / `key_bits` / `curve` + `encrypted`（是否带口令保护）+ `sources[]`；
  - `sources[]` 元素：`{kind: file|container|store, path, container_format, alias, entry_type, store_name}`。
- **分水岭**：**同一张证书出现在多个位置只保留一条记录，多处来源列成数组**；同一私钥亦然。这是与 §1.3 全部现有工具的差别所在（certigo 单文件、x509-certificate-exporter 只出指标、ChainWarden 只吃单个 PEM）。
- **确定性纪律**：
  - 哈希输入**一律是 DER 原始字节**（不做重新编码后再哈希——重编码会引入解析器版本差异）；
  - JSON 键序固定为 schema 声明顺序；`sources[]` 按 `(kind, path, alias)` 稳定排序；
  - 记录里**不写入解析时刻**、不写入主机名、不写入用户名（隐私红线，见 §六）；
  - 解析失败一律产 `PARSE_FAILED` 记录（含 `path` + 失败阶段），不吞。

### 模块③：卫生规则 `hygiene`

- **输入**：归一化台账 + 策略文件（阈值与出处）+ `--as-of`。
- **输出**：finding 列表（`code` / `severity` / `subject` / `fingerprint` / `evidence` / `rule_source`）。
- **规则集（首期）**：
  1. `EXPIRED` / `EXPIRING`：以 `--as-of` 为唯一时间基准；
  2. `EXPIRY_CLIFF`：**同一窗口内扎堆到期**（窗口与计数门槛来自策略，非代码字面量）——这条是"为什么单看过期表不够"的直接体现；
  3. `WEAK_KEY` / `WEAK_SIG`：**阈值一律带出处**（CA/B TLS BR §6.1.5 + NIST SP 800-131A Rev.2），默认 `WARN`，可按策略升为 `ERROR`，也可关闭；**不得自创阈值**；
  4. `PRIVATE_KEY_UNENCRYPTED` / `PERMISSION_TOO_OPEN`：私钥加密态 + 权限位（POSIX mode / Windows ACL）；
  5. `ORPHAN_CERT` / `ORPHAN_KEY`：有证书无私钥、有私钥无对应证书（**按 `spki_sha256` 配对**，不按文件名猜）；
  6. `DUPLICATE_CERT` / `DUPLICATE_KEY`：同指纹多副本（并列在 `sources[]` 里，规则只负责提示"该收敛"）；
  7. `CONTAINER_TRUSTSTORE_WITH_KEY` / `CONTAINER_EMPTY_PASSWORD`：容器层信号（M5 供数）；
  8. `PUBLIC_VALIDITY_HINT`：公网有效期政策提示（CA/B 200/100/47 天时间表），**信息级，不参与本地合规判定**；
  9. `SOURCE_UNAVAILABLE` / `PARSE_FAILED`：采集与解析的残差**必须出现在报告里**，否则"没找到"与"没看"无法区分。
- **过期表**：按 `not_after` 升序输出，支持 `--top N` 取最紧迫的 N 条——**`--top` 只影响展示，不裁剪 finding 全集、不影响退出码**（截断改变门禁结果等于给 CI 开后门）。
- **确定性纪律**：每条规则必须声明**判据出处**（RFC/CA-B/NIST 节号）；无出处的判据不得进入规则集；`--as-of` 必填，缺失即报错退出（**不允许默认取当前时间**）。

### 模块④：确定性报告与门禁 `report`

- **输入**：台账 + finding 列表 + 可选的 `--baseline prev.json`。
- **输出**：JSON + Markdown 双格式报告；`--as-of` **必须在报告头部回显**；`--baseline` 时输出 **新增 / 消失 / 轮换** 三类 diff。
- **退出码**：`0` 无 finding 达到门槛；`1` 达到 `--fail-on` 门槛（默认 `ERROR`）；`2` 输入/策略/参数错误。
- **确定性纪律**：排序稳定为 `severity → code → subject → fingerprint`；同一输入 + 同一 `--as-of` 两次运行**字节级相同**（含 Markdown）；报告不嵌入运行耗时、绝对路径可选打码、不嵌时间戳（`--as-of` 即时间戳）。

### 模块⑤：容器视图 `containers`

- **输入**：PKCS#12（RFC 7292）、JKS、JCEKS 文件。
- **输出**：alias 表（`alias` / `entry_type` / 指纹 / 链长 / 同指纹多别名）+ 容器级信号（truststore 混入私钥、空口令可读）。
- **实现路线**：PKCS#12 走标准解析；**JKS/JCEKS 首期走 `keytool -list -v` 输出解析**（允许 Java 依赖），**keytool 缺失时降级为一条 `CONTAINER_UNREADABLE` 记录而不是整体失败**（`plan/00` D2）。
- **确定性纪律**：`keytool` 输出按 `Alias name:` / `Entry type:` 等**键取值**，不依赖列宽与本地化排版；容器内条目顺序按 alias 排序；口令只从参数/环境读取，**不落盘、不进报告**。

### 扩展项（首期不做，防 scope 失控）

- `verify` 子命令：链验证，**复用 `openssl verify` 作 oracle**（`-CAfile` / `-untrusted` / `-attime` / `-CRLfile` / `-crl_check_all`）；
- 吊销**只做离线快照**：CRL 从本地 `.crl` / PEM 读；OCSP 只接受本地保存的 DER（`openssl ocsp -respin`）；任何联网拉取必须显式 `--online` 且**默认关闭**。

## 六、边界与非目标

- **不做远程 TLS 扫描**：testssl.sh 9241★ / sslyze 3792★ 已占该方向，且本题首期承诺**零网络**——任何联网能力都从设计上排除。
- **不做密钥泄露扫描**：gitleaks 30126★ / trufflehog 28592★ 已占。这条边界**最容易被误读成 secret scanning**，因此题面必须靠两件事把话题拉回台账：**①按 `spki_sha256` 做私钥↔证书配对；②“有几份 / 谁配谁 / 谁没人用”才是产出**，而不是"这个字符串像不像密钥"。
- **不做 SBOM / CBOM 输出**：cbomkit-theia 46★ / cdxgen 1090★ 已占该形态；本题只出 JSON + Markdown 台账。
- **不做守护进程 / 告警推送 / Web 面板**：那会把项目推进监控红海，且与"盘点一次、留一份可 diff 的快照"的定位冲突。
- **首期不做链验证与吊销**：二者已由 `openssl verify`（`-CAfile` / `-untrusted` / `-CRLfile` / `-crl_check_all` / `-attime`）+ certigo 1036★ 覆盖，首期正面撞上去收益低。`verify` 子命令与离线 CRL/OCSP 快照列 v2；**是否启用 `--online` 必须显式，默认关闭**。
- **不验签、不自建 CA 判定逻辑**：签名验证同样交给 `openssl verify` 作 oracle（v2），首期只做结构解析与配对。
- **隐私红线**：**纯本地、零网络、零遥测**；真实证书与私钥**永不入库**（`.gitignore` 拦截 `*.pem` / `*.key` / `*.p12` / `*.jks`，`fixtures/out/` 不入仓）；报告不写主机名、用户名、绝对路径默认打码。
- **品牌隔离**：本项目与本系列其他项目**互不提及、不共享命名与素材**；文档中不出现任何姊妹项目的领域描述。
- **首期范围限定**：仅上述 5 个模块 + `fixtures/gen.sh`；`verify`、离线 CRL/OCSP、更多后端（远程仓库、HSM）一律留扩展项。
- **结论纪律**：所有强度/有效期判据必须带出处；**无出处的阈值不得成为默认值**；"RSA 2048 已不推荐"这类说法不得使用——正确表述见 §1.5。
